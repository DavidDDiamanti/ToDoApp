# Todo App v5 Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A settings wheel in the toolbar opens an overlay with two settings: night mode (on, off, or follow the device) and the gap between items (small 0.7×, medium 1×, large 1.3× of the v4 default). Both persist per device.

**Architecture:** A new persisted `settingsStore` (zustand `persist` on `localStorage`, key `todo-settings`) holds `theme` and `gap`. One hook, `useApplySettings`, mirrors them onto `<html>` as `data-theme` and `data-gap`; `tokens.css` keys the dark palette and the `--gap-item` token on those attributes. A tiny inline script in `index.html` sets the same attributes before first paint. The dialog chrome of `ConfirmDialog` (backdrop, `role="dialog"`, Escape, Tab trap, focus restore, held-Enter guard) is extracted into `DialogFrame`; `SettingsDialog` and `ConfirmDialog` both build on it.

**Tech Stack:** unchanged (React 19, TypeScript strict, Zustand 5, Vitest 5, jsdom 30, RTL 16). No new dependencies.

Spec: `docs/superpowers/specs/2026-09-10-todo-app-design.md` section 15 (written in Task 5).

## Decisions (2026-09-12)

- Theme default follows the device setting; switching the toggle sets an explicit override; a "Use device setting" control clears it.
- Settings are stored per device in `localStorage`, not synced. They apply before sign-in and offline.
- Gap sizes are exact multiples of the v4 token: small = 6 px × 0.7 (4.2 px), medium = 6 px, large = 6 px × 1.3 (7.8 px).
- Work continues on `feat/ui-polish` / PR #2 (still unmerged, one visual pass before merge).

Assumptions stated for approval:

- The overlay is a centred dialog panel over a dimmed backdrop (same frame as the delete and unsaved-changes dialogs), closed by Done, Escape or a press on the backdrop; focus returns to the wheel.
- Night mode is a switch (`role="switch"`) whose position reflects the effective theme. Below it, while no override is set, a line reads "Following the device setting"; once overridden, a "Use device setting" button appears.
- Gap size is a three-option radio group labelled Small, Medium, Large.
- Opening settings while an editor is open leaves the editor as it is (no close request); the wheel press deselects the selected item like any other press off an item.
- The PWA manifest colours stay light; the `theme-color` meta tags are updated live to the resolved theme.

## Global Constraints

All constraints from the v1 to v4 plans still apply. Additions:

- Persisted user preferences live in `src/store/settingsStore.ts`; `uiStore` stays UI-only and unpersisted.
- The only places that touch `document.documentElement` are `useApplySettings` and the bootstrap script in `index.html`.
- The outside-press hook's exemption selector gains `[data-keeps-editor]` for chrome controls that must not close an editor (the wheel).
- Every new control has an `aria-label` or visible label and a non-empty `title`; touch targets 44 px.
- `npm test` and `npm run typecheck` green before each commit.

## Risks

- Duplicated dark palette in `tokens.css` (12 lines); any future palette edit must touch both blocks. A comment marks them.
- The inline bootstrap script runs before React; a corrupt `localStorage` value is caught and ignored, and `useApplySettings` re-applies the truth after hydration.
- The manifest `theme_color` stays light; Android's title bar colour comes from the live `theme-color` meta, which the hook updates.
- Fractional gaps (4.2 px, 7.8 px) render fine in Chrome; sub-pixel rounding can differ by row by 1 px.
